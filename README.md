# 金句转漫画画面

`quote-to-comic-scene` 是一个面向 ChatGPT/Codex 的构思型 Skill。它把一句抽象的金句转换成清晰、有隐喻且可以直接绘制的单幅漫画画面，并输出适合 `chat-comic-generator` 接续使用的结构化内容。

默认只生成画面构思，不直接出图；当用户同时要求生成漫画时，再衔接项目中的 `chat-comic-generator`。

## 适用场景

- 为一句金句设计漫画画面。
- 把抽象哲理转换成具体的视觉隐喻。
- 为水彩单幅漫画准备画面描述、文案和风格组。
- 针对同一句文案构思多个彼此不同的画面方案。

以下情况通常不使用本 Skill：

- 只需要润色、缩写或改写文案。
- 用户已经给出了明确的画面内容，只需要生成漫画。
- 需要多格分镜、连续剧情或复杂信息图。

## 核心特点

- 从金句的核心张力出发，而不是逐字图解。
- 每个方案只表达一个瞬间、一个主要动作或一个视觉隐喻。
- 优先采用单主体和少量必要道具，保证画面一眼可读。
- 构思天然适配竖版、白底、手绘墨线和淡水彩单幅漫画。
- 默认输出可被 `chat-comic-generator` 直接识别的字段。
- 保留用户金句原文，避免在构思阶段擅自改写。

## 安装

### 安装到当前项目

```powershell
git clone https://github.com/qinyugithub/quote-to-comic-scene.git .codex/skills/quote-to-comic-scene
```

目录结构：

```text
项目目录/
└── .codex/
    └── skills/
        └── quote-to-comic-scene/
            ├── SKILL.md
            ├── README.md
            └── agents/
                └── openai.yaml
```

### 安装为个人 Skill

```powershell
git clone https://github.com/qinyugithub/quote-to-comic-scene.git "$env:USERPROFILE\.codex\skills\quote-to-comic-scene"
```

安装后重新打开一个 Codex 任务，使 Skill 被重新发现。

## 基础用法

在对话中显式调用：

```text
使用 $quote-to-comic-scene

金句：不是所有的坚持都有结果，但总有一些坚持会让你成为更好的自己。
```

典型输出：

```text
画面内容：一个人站在白纸般空旷的地面上，身后散落着几双磨破的鞋，面前的自己比最初站得更直；他手里没有奖杯，只低头系紧脚上的鞋带。
底部文案：不是所有的坚持都有结果，但总有一些坚持会让你成为更好的自己。
风格组：metaphor
```

## 常用请求方式

### 只要一个画面构思

```text
使用 $quote-to-comic-scene，把“慢一点没关系，只要方向没有错”变成一个漫画画面。
```

### 提供多个方案

```text
使用 $quote-to-comic-scene，为这句金句提供 3 个彼此不同的画面方案：
真正的成长，是允许自己暂时没有答案。
```

### 指定风格或限制

```text
使用 $quote-to-comic-scene

金句：有些告别不是失去，而是生活在替你腾出位置。
风格组：poetic
氛围：安静、克制、略带释然
不要出现：车站、行李箱、第二个人物
```

### 构思后直接生成漫画

项目中同时安装 `chat-comic-generator` 后，可以这样请求：

```text
使用 $quote-to-comic-scene 和 $chat-comic-generator，先为下面的金句设计画面，再直接生成完整漫画：

生活不会因为你着急，就提前给你答案。
```

此时先完成画面构思，再由 `chat-comic-generator` 生成无字插画、排入中文并验收成品。

## 输出格式

默认输出一个方案：

```text
画面内容：<可直接绘制的主体、动作、关键道具和空间关系>
底部文案：<用户提供的金句原文>
风格组：<daily、poetic、metaphor 或 vivid>
```

用户有明确要求时，可以补充：

```text
氛围：<情绪与叙事气质>
点缀色：<主要强调色>
不要出现：<需要排除的元素>
```

本 Skill 会保留用户金句中的字词、标点和输入换行，用于准确交接；最终漫画是否显示标点、如何换行，由下游出图 Skill 的排版规则决定。

## 风格组

| 风格组 | 适用内容 | 构思倾向 |
| --- | --- | --- |
| `daily` | 日常、职场、动物拟人、轻微冷幽默 | 一个生活化动作，少量道具，容易理解 |
| `metaphor` | 选择、压力、得失、人生哲理 | 用人物与核心物件形成直接的视觉隐喻 |
| `poetic` | 孤独、成长、告别、内心感受 | 人物较小，空间更空，情绪温柔克制 |
| `vivid` | 儿童、动物闹剧、高能量幽默 | 动作夸张、节奏活泼、色彩更鲜明 |

未指定时默认使用 `daily`；明显以抽象哲理为核心时优先 `metaphor`。

## 构思原则

一个合格的画面描述应当：

1. 只呈现一个主要瞬间。
2. 让动作、大小或位置关系承担寓意。
3. 使用一位主体和一两件必要道具。
4. 能在竖版画布上集中于上半部呈现。
5. 不依赖画内文字、标牌、数字或对白解释。
6. 不重复描述下游技能已经固定的水彩技法和留白比例。

避免使用缺少具体动作的“人物望向远方”，也不要堆叠多个象征物，让画面必须经过长篇解释才能成立。

## 与 `chat-comic-generator` 的关系

```text
用户金句
   ↓
quote-to-comic-scene：理解含义并设计可绘制场景
   ↓
chat-comic-generator：生成无字插画并确定性排版中文
   ↓
800×1200 单幅水彩漫画
```

`quote-to-comic-scene` 可以独立使用；只有需要最终图片时，才需要安装并调用 `chat-comic-generator`。

## 常见问题

### 为什么默认只给一个方案？

单一方案更方便直接进入出图流程，也能避免多个相似构思增加选择成本。需要多个方案时，在请求中明确数量即可。

### 会修改我的金句吗？

不会。默认保留原文字词、标点和用户指定的换行。画面构思与文案分开处理。

### 为什么画面描述没有重复写水彩、白底和留白？

这些属于下游漫画 Skill 的固定视觉规范。当前 Skill 只描述真正需要绘制的可见场景，避免提示词重复和漂移。

### 可以直接生成图片吗？

本 Skill 默认只负责构思。若同时要求出图，并且项目中已安装 `chat-comic-generator`，Codex 会继续执行完整漫画生成流程。
